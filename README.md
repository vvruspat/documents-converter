# Documents Converter

Личный веб-сервис для превращения фотографий таблиц в Excel. Минимальный интерфейс: загрузка файлов, прогресс обработки, скачивание результата напротив каждого файла. Конвертация запускается автоматически. Каждая таблица фотографии экспортируется на отдельный лист `.xlsx`.

Сервис использует OpenRouter с vision-моделью `google/gemini-2.5-flash`. Модель можно заменить через `OPENROUTER_MODEL`, выбрав модель с поддержкой изображений и JSON Schema. На странице `/history` доступны исходник, результат, дата, скачивание и удаление. Метаданные истории хранятся в PostgreSQL, исходные фотографии и готовые Excel-файлы — в постоянном Docker-томе. Скачивания и история требуют входа. Удаление конвертации удаляет оба файла и запись истории. Содержимое документов, строки подключения и ключи не записываются в логи.

## Разработка

Нужен Node.js 24.

```sh
npm ci
DATABASE_URL=postgresql://postgres:dev-password@127.0.0.1:5433/documents_converter OPENROUTER_API_KEY=your-key npm run dev
```

Откройте `http://127.0.0.1:5173`. В режиме разработки без `APP_PASSWORD` пароль не требуется. Значения из `.env` не загружаются автоматически: используйте переменные процесса, `node --env-file` или механизм секретов вашей среды. Реальные ключи нельзя коммитить.

```sh
npm run typecheck
TEST_DATABASE_URL=postgresql://postgres:dev-password@127.0.0.1:5433/documents_converter_test npm test
npm run build
npm start
```

## Coolify

Создайте отдельное приложение из публичного Git-репозитория, ветка `main`, Build Pack **Dockerfile**, файл `/Dockerfile`, порт **3001**. Укажите HTTPS-домен. Не публикуйте порт контейнера напрямую на хост. В Coolify настройте HTTP healthcheck: host `127.0.0.1`, port `3001`, path `/api/health`, ожидаемый код `200`. Runtime-образ включает curl для проверки Coolify. Собственный HEALTHCHECK Dockerfile использует Node.js fetch.

Добавьте постоянный именованный том с mount path **`/app/data`**. Dockerfile создаёт эту папку с правами пользователя `node`. В томе хранятся фотографии и Excel-файлы; его нужно сохранять при деплоях и включать в резервное копирование вместе с PostgreSQL. Не запускайте несколько реплик с отдельными файловыми томами.

На сервере используется отдельная база **`documents_converter`** существующего кластера Supabase PostgreSQL 17 и отдельный пользователь без superuser, createdb и createrole. Подключение контейнера проходит по внутренней сети Docker к **`supabase-db:5432`**. Строка подключения хранится в Coolify как секретная runtime-переменная `DATABASE_URL`.

Переменные окружения задаются в Coolify только для runtime, без build-time:

| Переменная | Значение |
| --- | --- |
| `OPENROUTER_API_KEY` | Секретный ключ OpenRouter |
| `OPENROUTER_MODEL` | `google/gemini-2.5-flash` по умолчанию |
| `APP_PASSWORD` | Пароль входа, минимум 6 символов |
| `SESSION_SECRET` | Случайный секрет не короче 32 символов |
| `NODE_ENV` | `production` |
| `PORT` | `3001` |
| `TRUST_PROXY` | `1` для одного доверенного reverse proxy Coolify |
| `DATA_DIR` | `/app/data` в контейнере; `.local/data` при локальной разработке |
| `DATABASE_URL` | Обязательная секретная строка подключения к PostgreSQL |

В production сервис не запустится без настроенных `APP_PASSWORD` и `SESSION_SECRET`. Приложение использует HttpOnly Secure SameSite cookies. Пароль не передаётся в OpenRouter. Ограничения: 20 распознаваний за 10 минут с одного IP, 12 МБ на фото, JPG/PNG/WebP, не более 60 млн пикселей. Перед отправкой изображение поворачивается с учётом EXIF и уменьшается до 3200 пикселей по длинной стороне.

## GitHub Actions

Workflow `.github/workflows/deploy.yml` поднимает PostgreSQL 17 для интеграционных тестов, проверяет типы, тесты, production-сборку, зависимости и сборку Docker-образа. Тесты используют `TEST_DATABASE_URL`, создают отдельные временные схемы и удаляют их после проверки. После успешных проверок `main` отправляет в Coolify подписанный manual GitHub webhook. HMAC-секрет ограничен приложением и репозиторием; постоянный API-токен Coolify workflow не нужен.

1. В Coolify задайте уникальный **Manual GitHub Webhook Secret** приложения и разрешите auto deploy для manual webhook. Не создавайте обычный GitHub webhook на push, иначе он будет обходить CI.
2. В GitHub Secrets добавьте тот же секрет как `COOLIFY_WEBHOOK_SECRET`.
3. В GitHub Variables задайте `COOLIFY_WEBHOOK_URL=https://coolify.whitesquirrel.digital/webhooks/source/github/events/manual` и `APP_URL` с адресом приложения.
4. Не переопределяйте runtime-переменную Coolify `SOURCE_COMMIT`: `/api/health` использует её для проверки версии.

Webhook передаёт полный SHA проверенного коммита. Action завершается успешно только когда HTTPS health endpoint отвечает с этим SHA. Ключ OpenRouter остаётся в Coolify и не нужен GitHub Actions. Для отката можно перезапустить workflow для нужного коммита в `main` либо воспользоваться rollback в Coolify.

## Распознавание и экспорт

При первом запуске с PostgreSQL существующая `conversions.sqlite` открывается только для чтения. История переносится с сохранением UUID, имён, дат и путей к файлам. Таблица `legacy_conversion_imports` предотвращает дубли и повторное появление удалённых конвертаций при следующих запусках. После остановки старого контейнера одноразовый запуск свежего `ConversionStore` переносит поздние записи; `finalizeLegacyImport()` учитывает удаления старой версии и ставит отметку `sqlite-finalized`. После этого SQLite не читается при старте и остаётся резервной копией. Новые операции работают только с PostgreSQL. Очередь `pending_file_deletions` позволяет завершить очистку файлов после прерывания процесса. Приложение начинает принимать запросы после инициализации базы, а healthcheck проверяет реальное соединение PostgreSQL.

Сохраняются исходные строки, порядок, ведущие нули и пропуски в номерах. Сомнительные ячейки выделяются в Excel; их нужно проверить по фото. Текст внутри документа рассматривается как данные, а не команды для модели. Формулы из исходного фото экспортируются как буквальный текст и не исполняются. Однозначные даты `ДД.ММ.ГГГГ` и короткие числа сохраняются в Excel как типизированные значения; длинные идентификаторы и значения с ведущими нулями — как текст.

AI может ошибаться: проверьте номера, суммы и даты перед использованием результата. Неудачные запросы автоматически не повторяются. Каждое повторное распознавание — отдельный запрос OpenRouter.
