# Documents Converter

Личный веб-сервис для превращения фотографий и PDF с таблицами в Excel. Минимальный интерфейс: загрузка файлов, прогресс обработки, скачивание результата напротив каждого файла. Конвертация запускается автоматически. Каждая таблица документа экспортируется на отдельный лист `.xlsx`.

Сервис использует OpenRouter с моделью `google/gemini-2.5-flash`. В разделе «Таблицы в Excel» (`/convert`) PDF передаётся целиком как `file` с `file-parser/pdf.engine=native`: обрабатываются все страницы, включая сканы. При смене модели для PDF нужна нативная поддержка PDF. Модель можно заменить через `OPENROUTER_MODEL`, выбрав модель с поддержкой изображений, PDF и JSON Schema. На странице `/history` доступны исходник, результат, дата, скачивание и удаление. Метаданные истории хранятся в PostgreSQL, исходные фотографии/PDF и готовые Excel-файлы — в постоянном Docker-томе. Скачивания и история требуют входа. Удаление конвертации удаляет оба файла и запись истории. Содержимое документов, строки подключения и ключи не записываются в логи.

На главной странице (`/`) можно импортировать книгу Excel для строительного проекта или загрузить несколько PDF-комплектов. Для каждого PDF приложение создаёт отдельное задание и формирует реестр `.xlsx` с названием, номером, датой, организацией, количеством листов и страницами каждого документа. Для этого режима приложение не устанавливает предел размера файла или числа страниц: загрузка идёт на диск, страницы распознаются последовательно, а Excel создаётся потоковой записью. Задания и результаты сохраняются в `DATA_DIR/registry-jobs`; после перезапуска незавершённая обработка продолжится с последней сохранённой страницы. Одновременно выполняется одно задание. Для локальной разработки установите Poppler (`pdfinfo` и `pdftoppm`) и Tesseract с данными `osd`, `rus`, `eng`; Docker-образ включает их. Модель получает изображение страницы после проверки ориентации. При первом открытии листа в окне сравнения приложение показывает скан и запускает Tesseract для получения слов с координатами. Сервер обрабатывает по одной такой странице за раз и сохраняет результат для повторного открытия. Модель для реестров должна поддерживать изображения и JSON Schema. Каждая страница вызывает модель отдельно, поэтому большие PDF требуют больше времени и расходов OpenRouter. Готовый PDF можно пересоздать новым заданием, сохранив прежний результат для сравнения. Сомнительные поля подсвечиваются, их нужно сверить со сканом. Доступный объём ограничен свободным местом постоянного тома и настройками внешнего прокси; если прокси ограничивает тело запроса, это ограничение нужно снять отдельно.

При обработке новых реестров парсер отмечает печати, штампы и рукописные записи. На каждый найденный фрагмент уходит отдельный запрос OpenRouter с вырезкой нормализованного скана. Для небольших областей на листах с сохранённым углом поворота приложение готовит вырезку из исходного PDF в увеличенном разрешении. При открытии рамки показываются отправленная вырезка и сохранённая расшифровка. В карточке любого загруженного документа можно выделить область вручную. В «Настройках» приложения можно вставить три независимых ID OpenRouter для распознавания документов, чата по архиву и сложных фрагментов. Выбор сохраняется в постоянном томе и применяется без перезапуска. При загрузке тома модели для его автоматического разбора фиксируются. В карточке можно вручную проверить ту же вырезку другой моделью и посмотреть прежние расшифровки. До первого сохранения используются значения окружения: `OPENROUTER_MODEL` и, для фрагментов, необязательный `OPENROUTER_REGION_MODEL`.

## Исполнительная документация

В разделе «Строительство» (`/projects`) создайте проект и первый комплект или импортируйте книгу автогенератора ИД 5.x. При импорте можно приложить три исходные формы DOCX для воспроизведения их макета. Без загрузки используются встроенные формы. Импорт переносит реквизиты, участников, справочники и начатые строки работ. В книге хранятся сведения о сертификатах. Оригиналы PDF и изображений загружаются в карточках материалов. Там же можно распознать поля и проверить их по тексту до сохранения.

Проект открывается обзором комплектов. Разверните комплект и добавьте шаг плана. Название, шаблон акта, номер, дату, подписантов и приложения можно заполнить позже. В обзоре видны недостающие сведения и число готовых актов, включая связанные АОСР. В АООК можно указать входящие АОСР. Чтобы заменить форму, скачайте базовый DOCX в разделе шаблонов, сохраните именованные закладки Word и загрузите изменённый файл. В «Реквизитах и настройках» задаются организации, маска номера и правила формирования приложений. «Выгрузить комплект» собирает ZIP для выбранного комплекта или отмеченных работ. Внутри находятся акты, приложенные оригиналы и книга Excel с реестрами и журналами. Строки без загруженного оригинала отмечаются в реестре.

Новый API работает через NestJS внутри существующего сервера и использует общую авторизацию. Проекты и исходные файлы хранятся в PostgreSQL. Для извлечения реквизитов локально используются Poppler и Tesseract с русским и английским языками. В production-образ они уже включены.

## Разработка

Нужен Node.js 24.

```sh
npm ci
DATABASE_URL=postgresql://postgres:dev-password@127.0.0.1:5433/documents_converter OPENROUTER_API_KEY=your-key npm run dev
```

Откройте `http://127.0.0.1:5173`. В режиме разработки без `APP_PASSWORD` пароль не требуется. Значения из `.env` не загружаются автоматически: используйте переменные процесса, `node --env-file` или механизм секретов вашей среды. Реальные ключи нельзя коммитить.

```sh
npm run typecheck
TEST_DATABASE_URL=postgresql://postgres:dev-password@127.0.0.1:5433/documents_converter_test npm test
npm run build
npm start
```

## Загрузка страницы

Production-сборка преобразует синтаксис для Chrome/Edge 80+, Firefox 78+ и Safari 13.1+. Все ресурсы приложения загружаются с собственного домена, без внешних CDN. До запуска React виден обычный HTML с названием и кнопкой обновления. Небольшой `/startup.js` показывает ошибку загрузки ресурсов (`asset-load`), ошибку запуска (`app-start`) или превышение 15 секунд ожидания (`startup-timeout`). Отсутствующие JS/CSS возвращают настоящий 404, HTML и стартовый скрипт перепроверяются при загрузке. Запрос сессии ограничен 12 секундами; при сбое доступна кнопка повторного подключения. Ошибки рендера перехватываются и показывают сообщение с обновлением страницы.

Страница `/diagnostics` доступна без входа и JavaScript: показывает название и версию браузера из User-Agent для проверки случаев пустого экрана. Эти сведения не сохраняются; ответ не кешируется.

## Coolify

Создайте отдельное приложение из публичного Git-репозитория, ветка `main`, Build Pack **Dockerfile**, файл `/Dockerfile`, порт **3001**. Укажите HTTPS-домен. Не публикуйте порт контейнера напрямую на хост. В Coolify настройте HTTP healthcheck: host `127.0.0.1`, port `3001`, path `/api/health`, ожидаемый код `200`. Runtime-образ включает curl для проверки Coolify. Собственный HEALTHCHECK Dockerfile использует Node.js fetch.

Добавьте постоянный именованный том с mount path **`/app/data`**. Dockerfile создаёт эту папку с правами пользователя `node`. В томе хранятся фотографии, PDF и Excel-файлы; его нужно сохранять при деплоях и включать в резервное копирование вместе с PostgreSQL. Не запускайте несколько реплик с отдельными файловыми томами.

На сервере используется отдельная база **`documents_converter`** существующего кластера Supabase PostgreSQL 17 и отдельный пользователь без superuser, createdb и createrole. Подключение контейнера проходит по внутренней сети Docker к **`supabase-db:5432`**. Строка подключения хранится в Coolify как секретная runtime-переменная `DATABASE_URL`.

Переменные окружения задаются в Coolify только для runtime, без build-time:

| Переменная | Значение |
| --- | --- |
| `OPENROUTER_API_KEY` | Секретный ключ OpenRouter |
| `OPENROUTER_MODEL` | `google/gemini-2.5-flash` по умолчанию |
| `APP_PASSWORD` | Пароль входа, минимум 6 символов |
| `SESSION_SECRET` | Случайный секрет не короче 32 символов |
| `NODE_ENV` | `production` |
| `PORT` | `3001` |
| `TRUST_PROXY` | `1` для одного доверенного reverse proxy Coolify |
| `DATA_DIR` | `/app/data` в контейнере; `.local/data` при локальной разработке |
| `DATABASE_URL` | Обязательная секретная строка подключения к PostgreSQL |

В production сервис не запустится без настроенных `APP_PASSWORD` и `SESSION_SECRET`. Приложение использует HttpOnly Secure SameSite cookies. Пароль не передаётся в OpenRouter.

## GitHub Actions

Workflow `.github/workflows/deploy.yml` поднимает PostgreSQL 17 для интеграционных тестов, проверяет типы, тесты, production-сборку, зависимости и сборку Docker-образа. Тесты используют `TEST_DATABASE_URL`, создают отдельные временные схемы и удаляют их после проверки. После успешных проверок `main` отправляет в Coolify подписанный manual GitHub webhook. HMAC-секрет ограничен приложением и репозиторием; постоянный API-токен Coolify workflow не нужен.

1. В Coolify задайте уникальный **Manual GitHub Webhook Secret** приложения и разрешите auto deploy для manual webhook. Не создавайте обычный GitHub webhook на push, иначе он будет обходить CI.
2. В GitHub Secrets добавьте тот же секрет как `COOLIFY_WEBHOOK_SECRET`.
3. В GitHub Variables задайте `COOLIFY_WEBHOOK_URL=https://coolify.whitesquirrel.digital/webhooks/source/github/events/manual` и `APP_URL` с адресом приложения.
4. Не переопределяйте runtime-переменную Coolify `SOURCE_COMMIT`: `/api/health` использует её для проверки версии.

Webhook передаёт полный SHA проверенного коммита. Action завершается успешно только когда HTTPS health endpoint отвечает с этим SHA. Ключ OpenRouter остаётся в Coolify и не нужен GitHub Actions. Для отката можно перезапустить workflow для нужного коммита в `main` либо воспользоваться rollback в Coolify.

## Распознавание и экспорт

Конвертер принимает PDF, JPG, PNG и WebP без прикладных квот на размер файла, число страниц и длину очереди. Изображения поворачиваются с учётом EXIF и подготавливаются для распознавания. Структура PDF проверяется в отдельном потоке до обращения к модели. Повреждённые, пустые и защищённые паролем PDF отклоняются. В многостраничном PDF продолжения одной таблицы объединяются по порядку, отдельные таблицы попадают на отдельные листы. Если модель обрезала ответ, приложение сообщает об этом. Исходный PDF сохраняется для скачивания. Поле multipart `image` принимает изображения и PDF.

При первом запуске с PostgreSQL существующая `conversions.sqlite` открывается только для чтения. История переносится с сохранением UUID, имён, дат и путей к файлам. Таблица `legacy_conversion_imports` предотвращает дубли и повторное появление удалённых конвертаций при следующих запусках. После остановки старого контейнера одноразовый запуск свежего `ConversionStore` переносит поздние записи; `finalizeLegacyImport()` учитывает удаления старой версии и ставит отметку `sqlite-finalized`. После этого SQLite не читается при старте и остаётся резервной копией. Новые операции работают только с PostgreSQL. Очередь `pending_file_deletions` позволяет завершить очистку файлов после прерывания процесса. Приложение начинает принимать запросы после инициализации базы, а healthcheck проверяет реальное соединение PostgreSQL.

Сохраняются исходные строки, порядок, ведущие нули и пропуски в номерах. Сомнительные ячейки выделяются в Excel; их нужно проверить по исходнику. Текст внутри документа рассматривается как данные, а не команды для модели. Формулы из исходного документа экспортируются как буквальный текст и не исполняются. Однозначные даты `ДД.ММ.ГГГГ` и короткие числа сохраняются в Excel как типизированные значения; длинные идентификаторы и значения с ведущими нулями — как текст.

AI может ошибаться: проверьте номера, суммы и даты перед использованием результата. Неудачные запросы автоматически не повторяются. Каждое повторное распознавание — отдельный запрос OpenRouter.

### Электронный каталог

На главной выберите проект и загрузите отдельный документ или том. Во вкладке «Документы» доступны карточки с реквизитами и ссылками на исходные страницы. Старые задания без проекта доступны в «Общий». При первом открытии проекта приложение переносит сведения из завершённых заданий в PostgreSQL. Исходные PDF, постраничные результаты и Excel хранятся в DATA_DIR. Для восстановления архива нужны резервные копии базы и этого каталога. Проект группирует данные внутри приложения с общим паролем.

Комплект задаёт ожидаемые позиции до загрузки документов. Заполните вид документа и известные реквизиты, при необходимости секцию, этаж и вид работ. Система пересчитывает совпадения при появлении документов. При неоднозначности откройте скан и подтвердите документ вручную. Кнопка «Использовать как шаблон» копирует требования, подтверждения относятся к конкретному комплекту.

Вопрос по проекту ищет кандидатов по реквизитам и русскоязычному полнотекстовому индексу. Новые задания сохраняют в PostgreSQL текст страниц, границы документов и чтение печатей, штампов и рукописных фрагментов. После сохранения всех страниц модель «Чат по архиву» получает текст каждого документа с его фрагментами и заполняет реквизиты. Каталог и Excel используют одну сохранённую запись. Время и стоимость включают дополнительный текстовый запрос на каждый документ. Повтор после сбоя использует сохранённые страницы и уже заполненные записи. Ранее созданные задания продолжаются в прежнем формате. Приложение передаёт в OpenRouter выбранные выдержки и сведения из карточек. Ответы содержат ссылки на исходные страницы. Сервер использует OPENROUTER_API_KEY и OPENROUTER_MODEL. Старые результаты без сохранённого OCR доступны для поиска по реквизитам. Удаление задания также убирает его сканы из каталога.
